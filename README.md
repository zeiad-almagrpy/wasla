# وصلة WESLA

منصة عربية RTL تربط المشترين بالمحلات ومندوبي التوصيل. الإصدار 1.0: كل البيانات والحسابات على **Supabase** (لا `localStorage` للبيانات).

## الإعداد (مرة واحدة)

1. أنشئ مشروعًا على [supabase.com](https://supabase.com). **جرّب كل شيء أولًا على مشروع تجريبي منفصل** قبل مشروع الإطلاق.
2. **SQL Editor** ← الصق محتوى `supabase/schema.sql` كاملًا ← Run. (آمن على مشروع جديد وعلى مشروع طبّقت عليه نسخة قديمة: يحدّث الجداول ويمسح السياسات القديمة. إن كان فيه بيانات تجريبية قديمة غير مهمة، الأنظف أن تبدأ بمشروع جديد.)
3. **Authentication → Providers → Email**: عطّل **Confirm email**، واجعل الحد الأدنى لكلمة المرور 8.
   الدخول بالبريد الإلكتروني وكلمة المرور. رقم الهاتف يُطلب عند التسجيل للتواصل فقط (وهو فريد لكل حساب).
   **Authentication → URL Configuration**: ضع رابط موقعك في Site URL وفي Redirect URLs (لرابط استعادة كلمة المرور).
4. **Authentication → Attack Protection**: فعّل CAPTCHA (hCaptcha/Turnstile) لتقليل الحسابات الوهمية.
5. **Settings → API**: انسخ `Project URL` و`anon public key`.
6. أنشئ ملف `.env` من `.env.example` وضع القيمتين.
7. سجّل حسابًا في التطبيق، ثم اجعله **مديرًا** من SQL Editor:
   ```sql
   update public.profiles set role = 'admin' where phone = '201012345678';
   ```
8. من لوحة الإدارة: أضف رقم واتساب الدعم، وتأكد من المنطقة «مطوبس».

## التشغيل والبناء

```bash
npm install     # ثم ارفع package-lock.json
npm run dev
npm run build
```
يتطلب Node 20.19+ (يوصى 22).

## النشر (Vercel / Netlify)

Build: `npm run build` · Output: `dist` · أضف المتغيرين من `.env.example` في إعدادات المنصة (بدون `.env` في الريبو).

## كيف يعمل

- **الأمان**: الصلاحيات (RLS) في قاعدة البيانات. المتصفح لا يكتب الطلبات مباشرة؛ كل العمليات (إنشاء الطلب، تغيير الحالة، التفاوض على الأجرة، اعتماد المحلات والمناديب) دوال على الخادم تحسب الأسعار والإجمالي وتتحقق من الصلاحية.
- **الأدوار**: المشتري يسجل ويستخدم مباشرة. صاحب المحل يسجل محله فيظهر بعد اعتماد الإدارة. المندوب لا يرى أي مهمة قبل اعتماد الإدارة له (من «المستخدمون»).
- **الخصوصية**: هاتف المشتري يظهر للمحل، وللمندوب فقط بعد موافقة المشتري على الأجرة. العنوان يظهر للمناديب المعتمدين عند عرض المهمة.
- **التحديث**: الشاشات تتحدّث تلقائيًا كل 15–60 ثانية. لا توجد إشعارات دفع؛ تنبيه المحل بالطلب الجديد يتم بزر واتساب (يرسله المشتري) بالإضافة لعنوان الصفحة `(n) طلبات جديدة`.
- **الصور**: تُصغَّر في المتصفح وتُرفع إلى Supabase Storage (حد 1 ميجا).

## قبل إطلاق حقيقي (قائمة تحقق)

- [ ] جرّب سيناريو كامل بحسابات حقيقية على مشروع تجريبي: تسجيل مشتري/محل/مندوب ← اعتماد ← طلب ← تفاوض أجرة ← تسليم.
- [ ] جرّب من حساب مشتري أن تحاول تعديل `role` أو `status` أو طلب مباشرة من console؛ يجب أن تُرفض.
- [ ] راجع `public/privacy.html` و`public/terms.html` قانونيًا (مسودات).
- [ ] فعّل النسخ الاحتياطي (Supabase Pro أو تصدير دوري) وراقب الاستخدام.
- [ ] رسائل Supabase الافتراضية محدودة العدد في الساعة (تكفي لاستعادة كلمة المرور في التجربة). لإطلاق أكبر اربط خدمة SMTP (مثل Resend).
- [ ] ابدأ بعدد صغير من المحلات والمناديب وراقب أول أسبوعين.
