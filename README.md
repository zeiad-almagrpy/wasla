# وصلة WESLA — الإصدار 1.2

منصة عربية RTL تربط المشترين بالمحلات ومندوبي التوصيل. كل البيانات والحسابات على **Supabase**.

## الجديد في 1.2
- **الهوية الجديدة:** شعار وصلة (برتقالي + تيل) في الشريط العلوي وشاشة الدخول والأيقونات والـ PWA، والتيل بقى جزء من الألوان.
- **مشاركة موقع المشتري:** زر «شارك موقعي» (اختياري) يرسل إحداثيات GPS للمحل وللمندوب الذي قبل الطلب فقط، مع زر اتجاهات للمندوب.
- **جاهز فورًا:** المحل يقدر يعلّم الطلب جاهزًا من أول ضغطة بدون وقت تجهيز، والمناديب يتنبّهون فورًا.

## الجديد في 1.1
- **الدفع:** كاش عند الاستلام، أو **فودافون كاش** (تحويل يدوي لمحفظة المحل + تأكيد المحل). وصلة لا تلمس الفلوس.
- **توصيل المحل:** المحل اللي عنده دليفري يفعّله بأجرة ثابتة، والمشتري يختار بين مندوب وصلة / توصيل المحل / استلام.
- **مناطق توصيل بأجرة ثابتة** (تديرها الإدارة). التفاوض على الأجرة بقى للمناطق غير المسجلة فقط.
- **أكواد تسليم:** كود يعطيه المحل للمندوب عند الاستلام، وكود يعطيه المشتري للمندوب عند التسليم (5 محاولات ثم يُقفل).
- **أمان وخصوصية:** عنوان المشتري ورقمه لا يظهران للمندوب إلا بعد التزامه بالطلب وينتهي ظهورهما عند التسليم، ومنع انتحال اسم كاتب المنشور، وحدود معدل، وإغلاق قائمة الصور العامة، وسجل تدقيق لكل تعديلات الإدارة.
- **تدفق أكثر أمانًا:** مهلة رد المحل (إلغاء تلقائي)، تحرير عروض المناديب الراكدة، أدوات للإدارة لحل الطلبات العالقة، منع التغيّر الخفي للسعر، منع تكرار الطلب.
- **إشعارات:** أحداث جديدة (مهمة متاحة للمناديب، عرض أجرة، موافقة/رفض، إثبات دفع…)، لحظية عبر Realtime، تنبيه صوتي للمحل مع إبقاء الشاشة صاحية، وإشعارات جهاز عبر service worker. (Web Push الكامل = المرحلة 2، انظر أسفل.)
- **الواجهة:** هوية برتقالية نيون، أنيميشن، تنقل سفلي للموبايل، دعم الشاشات الصغيرة جدًا للكبيرة جدًا، PWA قابلة للتثبيت.
- **إدارة:** مناطق التوصيل، تمديد الاشتراك مع سجل مدفوعات، ردّ على رسائل الدعم (مع اسم/رقم المرسل)، فرض الاشتراك اختياريًا.

## الإعداد (مرة واحدة)

> **جرّب كل شيء أولًا على مشروع Supabase تجريبي منفصل.**

1. أنشئ مشروعًا على [supabase.com](https://supabase.com).
2. **Database → Extensions**: فعّل **pg_cron** (للإلغاء التلقائي للطلبات الراكدة وانتهاء الاشتراكات). لو لم تفعّله، الـ migration لن يفشل لكن المهام المجدولة لن تعمل.
3. **SQL Editor** ← شغّل **بالترتيب**:
   1. `supabase/schema.sql` (الأساس).
   2. `supabase/migrations/002_phase1.sql` (آمن للتكرار).
   3. `supabase/migrations/003_location_ready.sql` (آمن للتكرار، يحتاج 002).

   **لا تشغّل أي ملف خارج `supabase/`** (مثل `dev-tests/`): هي ملفات اختبار للمطوّر على Postgres محلي وستعطي أخطاء في Supabase.
   لو ظهر خطأ أثناء التشغيل: شغّل `supabase/diagnose.sql` (قراءة فقط، لا يغيّر شيئًا) وسيعرض ما تم تطبيقه وما ينقص، وأرسل لي نص الخطأ بالكامل.

   ⚠️ **لا تعيد تشغيل `schema.sql` بعد الـ migrations**: يمسح كل السياسات ويعيد دوال النسخة القديمة. لو فعلت، أعد تشغيل 002 ثم 003. ويفضّل بعد الإطلاق استخدام migrations فقط.
4. **Authentication → Providers → Email**: الحد الأدنى لكلمة المرور 8. تأكيد الإيميل معطّل حاليًا (مفهوم للإصدار التجريبي، لكنه يعني أن الإيميل والهاتف غير موثّقين، انظر «ما لم يتم»).
   **URL Configuration**: ضع رابط موقعك في Site URL وRedirect URLs.
5. **CAPTCHA (اختياري):** فعّل Turnstile من **Attack Protection** **و** ضع `VITE_TURNSTILE_SITE_KEY` في البيئة. ⚠️ لو فعّلتها في Supabase دون المفتاح في الواجهة، لن يستطيع أحد تسجيل الدخول.
6. **Settings → API**: انسخ `Project URL` و`anon public key` إلى `.env` (من `.env.example`).
7. سجّل حسابًا ثم اجعله مديرًا:
   ```sql
   update public.profiles set role = 'admin' where phone = '201012345678';
   ```
8. من لوحة الإدارة: أضف **مناطق التوصيل** وأجرتها، ورقم واتساب الدعم، وراجع «إعدادات المنصة».

## التشغيل والبناء
```bash
npm install
npm run dev
npm run build
```
Node 20.19+ (يوصى 22). النشر: Build `npm run build` · Output `dist` · المتغيرات من `.env.example`. ملف `vercel.json` يضيف CSP وترويسات أمان (اختبره بعد النشر: لو منعت شيئًا ستظهر أخطاء CSP في console).

## الاختبارات
```bash
npm run test:ui                                   # واجهات الأدوار الأربعة في jsdom (31 اختبار)
./dev-tests/db/run.sh "postgresql://…/scratch"  # قاعدة البيانات على Postgres محلي (90+ تأكيد). ⚠️ يمسح قاعدة الاختبار
```
اختبارات قاعدة البيانات تغطي: خصوصية العنوان والهاتف والأكواد لكل دور، تدفق كل أنواع التوصيل والدفع، المهل، الأدوات الإدارية، المحاولات الخاطئة، الحقن المباشر، وحدود المعدل. تعمل على Postgres محلي مع محاكاة بسيطة لـ Supabase (`auth.uid()`, `storage`)، **وليست بديلًا عن تجربة كاملة على مشروع Supabase حقيقي**.

## كيف يعمل الدفع (فودافون كاش)
1. صاحب المحل يضيف رقم محفظته في «إعدادات المحل».
2. المشتري يختار فودافون كاش ← بعد إرسال الطلب يرى الرقم والمبلغ (ثمن المنتجات) ويحوّل من تطبيق فودافون كاش، ثم يكتب رقم العملية.
3. المحل يراجع محفظته ويضغط «وصلتني الفلوس». **لا تسليم ولا استلام مندوب قبل التأكيد** (مفروض على الخادم).
4. أجرة التوصيل تُدفع كاش لمن يوصّل. لا يوجد ربط آلي ببوابة دفع، فالتحقق يدوي من المحل، والنزاعات تُحل بين الطرفين والإدارة.

## الإشعارات: الوضع والخطة
| المرحلة | الحالة |
|---|---|
| 1. داخل التطبيق لحظي + صوت + إشعار جهاز أثناء فتح التطبيق | ✅ منفّذ |
| 2. **Web Push** (يصل والتطبيق مقفول): جدول `push_subscriptions` + Database Webhook على `notifications` + Edge Function بمفاتيح VAPID. `public/sw.js` جاهز لاستقبال `push` | ⏳ لم يُنفّذ |
| 3. واتساب Business API لأهم الرسائل (طلب جديد لم يُرد عليه) | ⏳ لم يُنفّذ |

على أندرويد تحتاج بعض الهواتف (شاومي/أوبو…) استثناء التطبيق من توفير البطارية لضمان وصول الإشعارات. على iPhone يلزم «إضافة إلى الشاشة الرئيسية».

## ما لم يتم بعد (بصراحة)
- **توثيق الهاتف (OTP)** وتأكيد الإيميل: ما زال أي شخص يسجل برقم/إيميل غيره.
- Web Push الفعلي وواتساب (أعلاه).
- حذف/إخفاء هوية الحساب (الـ FK تمنع الحذف المباشر)، وMFA لحساب الإدارة.
- تحقق هوية المناديب (بطاقة) وتقييم المناديب والمحلات وقائمة سوداء.
- ساعات عمل المحل (يوجد فتح/إغلاق يدوي فقط)، وتعدد الأدوار للحساب الواحد.
- روابط hash للتنقل (زر الرجوع يخرج من التطبيق)، وESLint.
